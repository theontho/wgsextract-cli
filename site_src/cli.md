## Global options
{{ lede: Shared options can go before or after the subcommand. `--threads` and `--memory` accept `auto` (the default). Every command exits non-zero on failure (1 failure, 2 usage error, 3 missing tool), so commands can be chained safely in scripts. `--json` prints a machine-readable result manifest on stdout instead of human text; commands that write files also save it as `<output>.manifest.json`. Examples write plain `wgsextract`; see [Running the CLI](install.html#running){.inline-link} for the launcher that matches your install. }}

For long jobs, `--log-file out/run.log` records diagnostics and provenance, `--tmp-dir /data/work` selects a writable staging volume, and opt-in `--keep-awake` requests sleep inhibition. `--atomic-output` protects existing results for supported writers. Memory/disk preflight is advisory; it does not replace existing safety guards.
:::

::: code-panel title=global-options.sh subtitle="common flags"
```
wgsextract \
  --input /data/sample.cram \
  --outdir /data/out/sample \
  --ref /refs/hs38.fa \
  --threads auto \
  --memory 2G \
  info --detailed
```

## Start from what you have
Pick the line that matches your file and run its commands in order. Each command's `--help` lists its options, examples and output files.
:::

::: grid three
::: card
### Nothing yet (a first run)
- `deps check`: check that the external tools are installed
- `ref bootstrap`: download the small shared files, e.g. liftover chains
- `ref library`: download a reference genome
- `example-genome download`: get a public example genome to practise on
:::

::: card
### A BAM or CRAM from a sequencing service (Nebula, Dante Labs, Sequencing.com, ...)
- `info`: check the reference build, file health and coverage
- `microarray`: make 23andMe/AncestryDNA-style files to upload
- `lineage y-haplogroup`: find the paternal haplogroup
- `lineage mt-haplogroup`: find the maternal haplogroup
- `vcf snp`: call SNPs into a VCF
- `vep run`: predict each variant's effect on genes
- `report`: summarise everything in one HTML report
:::

::: card
### A BAM or CRAM on the wrong build (hg19 when you want hg38, or the reverse)
- `info`: see which build it is
- `realign`: re-map it to the other build
- `info`: check the new file, then continue as above
:::

::: card
### FASTQ files (raw reads)
- `align`: map the reads to a reference, making a BAM/CRAM
- `info`: check the result, then continue as for a BAM/CRAM
:::

::: card
### A VCF (from a provider or another pipeline)
- `vcf clinvar`: add ClinVar clinical significance
- `vcf filter`: keep a gene, region or quality range
- `vep run`: predict each variant's effect on genes
- `vcf table`: one row per variant, for spreadsheets and SQL
:::

::: card
### A consumer raw-data file (23andMe, AncestryDNA, ...)
- `info chip`: identify the vendor, chip and revision
:::

## Command groups
`wgsextract --help` lists the core commands first, in the order you would usually run them, then setup and advanced commands. Run `wgsextract help --all` for one line per command (`--json` for a machine-readable index with each command's options and, for typed commands, a JSON Schema), `wgsextract help <command>` for one command's options, examples and output files (`--help-all` adds the advanced options), `wgsextract help topics` for concepts such as references, builds and exit codes, or `wgsextract help` for the full tree. The [command reference](https://github.com/WGSExtract/wgsextract-cli/blob/main/docs/commands.md){.inline-link} lists every command with its outputs and an example. A mistyped command or option gets a "Did you mean" hint, and on a terminal some commands suggest what to run next.
:::

::: grid three
::: card
### Start here, in this order
- `info`: Check a BAM/CRAM: reference build, file health, coverage.
- `microarray`: Make 23andMe/AncestryDNA-style raw-data files to upload.
- `lineage`: Find your paternal (Y-DNA) and maternal (mtDNA) haplogroups.
- `extract`: Copy Y, mtDNA, unmapped or one region's reads to a file.
- `realign`: Re-map a BAM/CRAM to another build, e.g. hg19 to hg38.
- `align`: Map raw FASTQ reads to a reference, making a BAM/CRAM.
- `vcf`: Call variants into a VCF, then annotate and filter them.
- `vep`: Predict what each variant does to genes, with Ensembl VEP.
- `report`: Summarise a sample's results in one local HTML report.
:::

::: card
### Setup
- `ref`: Download and check reference genomes and annotation data.
- `deps`: Check that the external tools are installed.
- `example-genome`: Download public example genomes to practise on.
- `sample`: Show recorded sample facts; correct sex or platform.
- `config`: Show the settings in use and the config.toml path.
- `report-issue`: Report a problem: a redacted, pre-filled GitHub bug report.
- `help`: List every command, or explain one: 'help vcf snp'.
:::

::: card
### Advanced
- `bam`: Sort, index, convert and merge BAM/CRAM files.
- `qc`: Read and VCF quality reports; fake test data.
- `repair`: Fix FTDNA BAM/VCF formatting problems.
- `analyze`: Run several analyses in one go, for one or many genomes.
- `typing`: Genotype CYP2D6, HLA and repeat expansions (30x WGS).
- `methylation`: 5mC/5hmC methylation from Nanopore and PacBio reads.
- `basecall`: Nanopore POD5 signal to reads with Dorado (optional).
- `panel`: Gene lists to BED targets for Nanopore adaptive sampling.
- `pet-align`: Align and call variants for a cat or dog genome.
- `sign`: Checksum and sign output files; verify them.
- `benchmark`: Time the main workflows on test data.
- `serve`: Local HTTP/JSON and MCP server for apps and AI agents.

Advanced subcommands of core groups: `extract bam-subset`, `vcf alphamissense`, `vcf cadd`, `vcf chain-annotate`, `vcf clair3`, `vcf cnv`, `vcf deepvariant`, `vcf freebayes`, `vcf gatk`, `vcf gerp`, `vcf pharmcat`, `vcf phase`, `vcf phylop`, `vcf spliceai`, `vcf sv`, `vcf to-fasta`, `vcf trio`.
:::

::: card
### Deprecated
- `ref library-list`: use `ref library --list`; removed in 0.8.0.
- `vep` without a subcommand: use `vep run`; removed in 0.8.0.
:::

## Common CLI recipes
These examples are intentionally small and explicit. Replace paths and references with your own. Output names keep the full input stem, so `HG002.chr20.bam` produces `HG002.chr20_sorted.bam`.
:::

::: code-panel title=recipes.sh subtitle="copy, edit, run"
```
# Identify a BAM/CRAM and inspect metadata
wgsextract --input sample.cram info --detailed

# Sort and index an alignment (sample.bam -> out/sample/sample_sorted.bam)
wgsextract --input sample.bam --outdir out/sample bam sort
wgsextract --input out/sample/sample_sorted.bam bam index

# Convert BAM to CRAM for storage
wgsextract --input sample.bam --ref /refs/hs38.fa bam to-cram

# Generate consumer microarray-style outputs
wgsextract --input sample.bam microarray --formats 23andme_v5,ancestry_v2

# Extract mitochondrial variants and Y-DNA reads
wgsextract --input sample.bam extract mito-vcf
wgsextract --input sample.bam extract ydna-bam

# Call and filter variants
wgsextract --input sample.bam --ref /refs/hs38.fa vcf snp
wgsextract vcf filter --vcf-input calls.vcf.gz --expr 'QUAL>30'

# Show the full command tree
wgsextract help
```

## Pixi environments
Some specialized tools live in dedicated Pixi environments. Install them explicitly with `pixi install --locked -e <environment>` before use. WGS Extract can route tools such as `vep` or `pbsv` through an existing environment, but validates dependencies rather than installing them during a feature. You can also run a whole command inside an installed environment, from the `app/` folder or a source checkout.
:::

::: grid three
::: card
### default
General CLI, samtools/bcftools, bwa/minimap2, fastp/fastqc, Delly where supported, native Yleaf-derived analysis, Haplogrep, and common workflows. Yleaf tables are verified on-demand data assets, not an external tool or bundle dependency. GATK and FreeBayes are separate.

```
pixi run wgsextract deps check
```
:::

::: card
### pacbio
PacBio-aware structural variant workflows using pbmm2, pbsv, and sniffles where available.

```
pixi run -e pacbio wgsextract vcf sv --pacbio
```
:::

::: card
### vep
Ensembl VEP for `vep run`, `vep download`, and `vep verify`. Not available on native Windows.

```
pixi run -e vep wgsextract vep run
```
:::

::: card
### gatk and freebayes
GATK (Python 3.10, Java 17) and FreeBayes live in their own environments. Install the locked environment before calling; neither is downloaded on first use. The Windows installer prepares GATK with its native GKL sidecar. FreeBayes is not supported on native Windows; GATK is gated on Linux ARM64.
:::

::: card
### cyrius, t1k, and expansionhunter
Gene and repeat typing: `typing cyp2d6` (Cyrius), `typing hla` (T1K), and `typing str` (ExpansionHunter). Linux x86_64 and macOS, where packaged; not qualified on Linux ARM64. Install once with `pixi install --locked -e <environment>`; Cyrius is licensed for noncommercial use only.
:::

::: card
### modkit
`methylation pileup` tabulates CpG methylation from Nanopore and PacBio MM/ML tags with ONT's modkit. Linux and macOS only; install it with `pixi install --locked -e modkit`.
:::

::: card
### dev
Contributor tooling: pytest, ruff, mypy, pre-commit, actionlint. Development tasks select it automatically.

```
pixi run test
pixi run lint
```
:::

::: section-head
## CLI best practices
Genome jobs are expensive. These habits prevent wasted hours and corrupted assumptions.
:::

::: grid four
::: card
### Use regions first
Try `chrM`, `chrY`, or a small gene region before whole-genome commands.
:::

::: card
### Keep outputs isolated
Use `--outdir` per sample or `--genome` folders to avoid mixing files.
:::

::: card
### Match builds
Keep BAM/CRAM, FASTA, VCF, gene maps, and annotations on the same reference build.
:::

::: card
### Log the command
Save exact commands, Pixi environment, reference build, and tool versions for repeatability.
:::
