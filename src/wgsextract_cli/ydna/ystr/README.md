# Y-STR repeat counts

`lineage y-str` reports genealogy Y-STR repeat counts from an indexed WGS BAM or
CRAM. It covers FamilyTreeDNA Y-12, Y-25, Y-37, Y-67 and Y-111, plus the forensic
PowerPlex Y23 (`PPY23`) and Yfiler Plus (`YfilerPlus`) kits (`--panel all`
selects every marker). It runs on GRCh37/hg19, GRCh38 and T2T-CHM13v2
alignments, with `chrY` or `Y` contig names. CRAM needs the matching `--ref`.

```sh
wgsextract --input sample.cram --ref /path/to/reference lineage y-str --panel Y-37
```

Outputs in `<outdir>/ystr/`:

* `<sample>.ystr.tsv` has one row per marker or copy. It includes the value
  (FTDNA convention) and `nist_value`, and the status and reason. It also has
  spanning and supporting read counts, every observed read length
  (`read_alleles`), and the source of the reference allele.
* `<sample>.ftdna.csv` has one row in FTDNA column order. Copies are joined
  with `-` (for example `DYS385` = `11-14`). Any copy that is not called leaves
  the cell empty.
* `run.json` records the thresholds, build, call count and panel source URLs.

Statuses:

| Status | Meaning |
|---|---|
| `called` | The value was called. |
| `low_support` | Too few reads agree on one length. |
| `too_long` | The repeat is longer than the reads can span. |
| `conflicting` | Reads disagree, or one-flank reads show a longer allele. |
| `no_spanning` | No read covers the repeat and both of its flanks. |
| `no_reads` | No reads at the marker. |
| `not_in_build` | The marker could not be placed in this build. |
| `not_callable` | The marker cannot be called from short reads (see below). |

The run fails, without writing a result that looks successful, when fewer than
10% of the selected markers are called. That usually means a female sample or
no chrY reads.

## Method

`samtools view` reads each repeat region. A read counts toward a marker only
when it contains both unique flanking sequences (14-mers, one mismatch
allowed). The repeat count is

    reference count + (tract length in read − tract length in reference) / period

so insertions and deletions in the repeat and in its non-repeating interior both
count. That matches capillary sizing (for example, DYS458 `17.2`).

* **Compound markers.** DYS389II, DYS448, DYS449, DYS504, DYS510, DYS518,
  DYS532 and DYS552 report the sum of their blocks, as FTDNA and the kits do.
* **Multicopy markers.** DYS385, DYS459, YCAII, DYF395S1 and DYS413 have
  reads that map to any copy, so they are pooled across copies.
  Values are reported in ascending order. A single value is reported for every
  copy only when at least 6 reads support it and no read shows another length.
  A length with weak support that sits one repeat from a stronger one is
  treated as stutter.
* **Too-long check.** Reads that contain only one flank set a lower bound on
  the length. Two or more bounds above the call make it `conflicting` (single
  copy) or `too_long` (multicopy), not a falsely short value.
* **Filters.** Defaults are `--min-reads 2`, `--min-fraction 0.6` and
  `--min-mapq 20`. The MAPQ filter applies to single-copy markers only.

Not callable from short reads:

* DYS464a-d (four or more palindromic copies)
* CDYa/b (long tracts in palindrome P1)
* DYF387S1
* Y-GGAAT-1B07 (its GRCh37 window has no GRCh38 match)

Build gaps:

* T2T lacks DYS459, DYS448, DYS425 and DYS589.
* hg19 lacks DYS425 and DYS716.

### Why not `typing str` (ExpansionHunter)

`typing str` runs ExpansionHunter with a catalog of pathogenic expansions. It
needs a separate Pixi environment on Linux or macOS. This counter needs only
samtools, so it runs on every platform, including Windows. It also handles
compound and multicopy Y-STRs, and per-marker FTDNA/NIST conventions, which
ExpansionHunter's locus model does not express. HipSTR was also considered, but
it is not available for Windows and would add a dependency.

## Panel data and licences

`markers.tsv`, `loci.tsv` and `provenance.json` are generated by
`scripts/build_ystr_panel.py` from the sources below. Each source is pinned by
URL and SHA-256 in `provenance.json`. Repeat tracts are located in each
reference by sequence, not by lifting coordinates over. No upstream file is
bundled; only derived coordinates, motifs and allele numbers are.

| Source | Used for | Licence |
|---|---|---|
| [HipSTR-references](https://github.com/HipSTR-Tool/HipSTR-references) (Willems et al. 2016) | GRCh38 repeat windows | MIT |
| [NIST STRBase](https://strbase.nist.gov) API and Y-STR fact sheet (Butler, Kline & Decker 2008) | Reference alleles in GenBank BACs, kit membership, FTDNA vs NIST offsets | Public domain (U.S. government work) |
| GenBank BAC sequences (accessions in `provenance.json`) | Anchoring NIST reference alleles to each build | Public (INSDC) |
| [Y-LineageTracker](https://github.com/Shuhua-Group/Y-LineageTracker) (Chen et al. 2021) | Windows and motifs | MIT |
| [Y-STR_Kit](https://github.com/savolab/Y-STR_Kit) | GRCh37 windows and repeat regexes | README says MIT; the repository has no LICENSE file. Only its windows and regexes are used, and nothing from it is bundled. |
| 1000 Genomes PowerPlex Y23 typings | DYS448 and DYS481 reference counts (calibration) | Open access, IGSR data policy |

Panel membership and column order follow FamilyTreeDNA's published Y-STR
results guide; only marker names and their order are used.
FTDNA values that differ from NIST nomenclature are adjusted per marker
(`ftdna_minus_nist`: Y-GATA-H4 −1, DYS442 −5, Y-GATA-A10 −2, DYS441 −1).

**Unverified values.** 36 markers, mostly in Y-67 and Y-111, have no
NIST-anchored reference allele. Their counts follow the cited tools' convention,
which can differ from FTDNA's by a constant. The CLI flags them as "unverified
FTDNA convention", and `value_convention` names the source.

To regenerate the panel (needs samtools and the three reference FASTAs):

```sh
pixi run -e dev python scripts/build_ystr_panel.py \
  --hg38 GRCh38.fa --hg19 hs37d5.fa --t2t chm13v2.0.fa --cache tmp/ystr-sources
```

## Accuracy

Truth data are the 1000 Genomes PowerPlex Y23 typings of 37 male samples
(`YSTRs_PowerPLexY23_1000Y_QA_20130107.txt`), compared with 30x high-coverage
1000G alignments. That covers 851 genotypes at the 23 PPY23 loci; DYS385 counts
as two. Accuracy is the share of called genotypes that match; no-calls are
counted separately.

| Data (`--min-reads 2`) | Concordant / called | No-calls |
|---|---|---|
| GRCh38, full 30x | 782 / 783 (99.87%) | 68 (8%) |
| GRCh38, downsampled to 50% | 603 / 604 (99.83%) | 247 (29%) |
| GRCh38, downsampled to 25% | 313 / 314 (99.68%) | 537 (63%) |
| Reads realigned to GRCh37 | 785 / 786 (99.87%) | 65 |
| Reads realigned to T2T-CHM13v2 | 759 / 760 (99.87%) | 91 (DYS448 absent) |
| GRCh38, `--min-reads 1` | 828 / 831 (99.64%) | 20 |

The one remaining error at `--min-reads 2` is DYS458 in one sample, called
`17.2` against a typed 17. Its reads carry a real 2 bp insertion, so this is
likely a difference between capillary sizing and sequence. Most no-calls are at
long tracts that 150 bp reads rarely span (DYS389II, DYS448, DYS576, DYS635,
DYS570).

The Y-67 and Y-111 markers outside PPY23 have no public truth set, so their
accuracy is untested; this includes the unverified values above. Treat the
results as an estimate for comparison, not as a replacement for a lab test.
